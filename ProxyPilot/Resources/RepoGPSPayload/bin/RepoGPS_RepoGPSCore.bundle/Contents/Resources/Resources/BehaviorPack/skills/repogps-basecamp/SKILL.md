# Basecamp

Prefer the repository's existing governance. When invited to establish Basecamp, preview every missing artifact, ask once before writing, create missing files without clobbering existing work, and record a rollback receipt.

Waypoints record entry state, intended scope, changed files, verification, blockers, and the next safe action. They do not replace repository instructions, development history, release procedures, or user authorization.

During ordinary coding, use RepoGPS's scoped Navigator recording tool at
meaningful boundaries: after a corrected understanding, consequential change,
verification result, changed direction, or completed turn. Cite the evidence
records that support the note. Tool output is observed evidence; a Navigator
note is advice about it. A note cannot mark tests passed, work completed, or an
action authorized.

Before a return or landing, refresh Git state and applicable instructions,
state which checks actually ran and their outcomes, identify unrelated dirt,
and preserve incomplete work honestly. An interrupted session leaves a partial
journal; do not reconstruct it as a successful landing.
